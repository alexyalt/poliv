# Система автополива «Полив»

Модульная веб-система управления поливом: сервер на FastAPI, база данных SQLite,
веб-интерфейс на Jinja2, контроллеры TESTBOX.

## Быстрый старт

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.lock
cp config/config.default.toml config/config.local.toml   # затем отредактируйте секреты
python -m pytest server/tests -q                          # полный набор проверок, включая 8.S
python server/main.py                                     # сервер на http://127.0.0.1:8080
```

При первом запуске на чистой БД создаётся пользователь `admin`; сгенерированный пароль выводится один раз в stdout, а не в лог. При первом входе обязательна собственная смена пароля через `/account/password`. Вход — через страницу `/login`. Проверка работоспособности: `GET /health`.

## Конфигурация и секреты

- `config.default.toml` — общие значения, хранится в git.
- `config.local.toml` — локальные overrides и секреты; **исключён из git** через `.gitignore`.
- Новые runtime-файлы игнорируются. В истории и текущем дереве пока есть ранее отслеженные БД/логи/расписания: `.gitignore` их не удаляет. Перед изменением индекса и обновлением установленной системы сначала сделайте резервную копию; см. `docs/spec/current-status.md`.

## Режимы размещения

Система поддерживает два режима работы (ADR-15):

### Локальный режим (по умолчанию)
- Сервер и MQTT-брокер работают в локальной сети
- Контроллеры подключаются по Wi-Fi к локальному брокеру
- Рекомендуется для приватности и минимальных задержек
- Не требует интернета

### Облачный режим
- Сервер размещается на VPS/облаке
- Контроллеры подключаются через интернет
- Позволяет управлять системой из любой точки мира
- Требует настройки TLS и аутентификации MQTT
- Настройка: `deployment.mode = "cloud"` в `config.local.toml`

## Стабилизация 8.S

Актуальное состояние и незакрытые риски: [current-status](docs/spec/current-status.md).
Изменения контракта архива и восстановления: [ADR-18](docs/adr/ADR-18-stage8-stabilization.md).
Перед обновлением сделайте согласованную резервную копию SQLite и архивов. Миграция
0011 добавляет метаданные; старые архивные пути и файлы не перемещаются.
Новый архив состоит из неизменяемого CSV/JSON и соседнего manifest, сохраняющего
NULL и связи зон. Копировать их нужно вместе. Относительный archive.path для новых
выгрузок разрешается от data_dir; старые пути в журнале остаются действительными.

Проверяемая конфигурация: Python 3.13, один worker Uvicorn. `requirements.txt` задаёт
диапазоны, `requirements.lock` фиксирует полный набор. Для обновления lock используйте
pip-tools в Python 3.13: `python -m piptools compile --strip-extras --output-file=requirements.lock requirements.txt`,
затем чистую установку, `pip check` и полный pytest. GitHub Actions настроен в `.github/workflows/tests.yml`: tests, browser и mqtt. Статус последнего запуска смотрите во вкладке Actions.

Для HTTPS за reverse proxy задайте `[server] cookie_secure = true` и доверяйте forwarded
headers только вашему proxy. Локальный HTTP остаётся доступным. Изменяющие браузерные
запросы с посторонним Origin/Referer отклоняются; клиенты без этих заголовков остаются
совместимыми. Не используйте wildcard CORS с сессионными cookie.

Чистую установку выполняйте с новым POLIV_DATA_ROOT либо отдельно подготовленным
каталогом данных: историческая data/poliv.db из Git не является безопасным production seed.
POLIV_DATA_ROOT задаётся до импорта приложения. Существующую рабочую БД заменять нельзя.


### Завершение 8.S

Оставшиеся программные изменения, ledger 0012 и правила обновления описаны в
`docs/spec/current-status.md` (последнее дополнение). Доступны отдельный отчёт
«Пропущенные поливы», период heatmap «7 дней», восстановление flow/weather,
/ready и ограничение командных workers. Для безопасной подготовки независимых
данных: остановить приложение и выполнить
`python -m server.tools.prepare_runtime --destination /absolute/outside/checkout`.
Команда сохраняет источник. После проверки копии настроить POLIV_DATA_ROOT до
обновления checkout. Пользовательские абсолютные пути/архивы вне checkout копировать
отдельно; старые пути в archive_exports сохраняются и требуют проверки доступности.

Опциональный UI smoke без реального сервера: установить playwright, выполнить
`python -m playwright install --with-deps chromium`, затем
`python -m server.tools.browser_smoke`. Playwright не добавлен в runtime lock.


### Финальная приёмка 8.S в main

Активный workflow: `.github/workflows/tests.yml` (push/PR/manual), минимальные права,
без deploy и секретов. Проверяет lock/pip, полный pytest/миграции, Chromium UI и
настоящий отдельный loopback Mosquitto. Локально MQTT:
`python -m server.tools.mqtt_smoke` (нужен executable mosquitto в PATH).

`prepare_runtime` теперь обновляет пути скопированных локальных архивов и расписаний
в копии БД. Проверяйте `runtime-copy.json`: ready=true и список external_files.
Исходники/исходная БД сохраняются; при ошибке ready=false и копия не пригодна к запуску.
Текущая итоговая матрица F01–F16 — `docs/spec/current-status.md`, история — WorkBook.


## Этап 9 — блокировки зон и нормализация

Реализованы 9A/9B в `feature/stage9-locks-normalization` от 9cab288. Страница
`/stage9` для operator/admin: интервальные auto/all/service блокировки, быстрые
час/24 часа, снятие, предложения day/week с before/after и подтверждением.
Миграция 0013 additive, старые данные сохраняются. Полная приёмка и ограничения:
[инструкция](docs/ИНСТРУКЦИЯ_ЭТАП9.md), [ADR-19](docs/adr/ADR-19-stage9.md).

Optimizer отдельный, переносит целые runs внутри исходного дня/окна. Не меняет
water/soak, parallel membership, погоду и программы. Нужно >=3 корректных одиночных
события каждой зоны за 90 дней. Apply требует confirm, отвергает stale snapshot,
создаёт версии полного горизонта и использует existing next_run delivery. Future
heatmap — подтверждённый ACK план, не факт. Offline box не получает физический запрет
до доставки; UI возвращает delivery/ошибки. Firmware safety/клавиатура — этап 10.

`python -m server.tools.stage9_smoke` проверяет Chromium→FastAPI→SQLite с fake MQTT;
Mosquitto smoke также проверяет stage9 manual block/release на настоящем broker.
CI runs feature/**, tests/browser/mqtt. Сохранение прогресса: каждый checkpoint
commit включает запись WorkBook и промежуточный push; docs/STAGE9_PROGRESS.md.
