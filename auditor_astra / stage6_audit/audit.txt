4. P1: MQTT ACK МОЖЕТ ЗАВЕРШИТЬ ЧУЖУЮ КОМАНДУ И ПРИНЯТЬ НЕИЗВЕСТНЫЙ СТАТУС

Pending индексируется только command_id; в записи нет ожидаемого box_id/command. Обработчик не сверяет источник ACK с адресатом команды. Для неизвестного status пишет warning, но не return и затем ставит final=True.
Воспроизведено: ACK из OTHER-BOX с command_id=audit-ack, command=ping и status=alien делает pending {final:True,status:alien,...}.
Исправить привязку pending к box_id и command, whitelist статусов с немедленным отказом, проверки типов; сохранить правило первого корректного финального ACK. Неизвестный/чужой ACK не должен менять состояние.

14. P2/P3: ЗАЩИТА СЕССИЙ И ВОСПРОИЗВОДИМОСТЬ
Файлы: web/routes.py:152; services/auth_service.py:148; requirements.txt.
Cookie HttpOnly и SameSite=Lax есть, Secure отсутствует. Нет явной CSRF-защиты на изменяющих cookie-auth запросах. SameSite снижает риск, поэтому полноценную межсайтовую эксплуатацию здесь не утверждаю, но для управляющей системы нужны CSRF/Origin проверки и Secure при HTTPS; не ломать документированный LAN HTTP режим без согласованной конфигурации.
get_user_by_token по умолчанию обновляет sessions на каждом polling-запросе: лишняя запись в SQLite и конкуренция. cleanup_sessions вызывается при старте, а не периодически. Ограничитель входа process-local. Проверить допустимость этих свойств для однопроцессного развёртывания; многопроцессный запуск с одним MQTT client_id должен быть явно запрещён или спроектирован.
requirements с широкими нижними границами и старым passlib/bcrypt не дают воспроизводимой проверенной среды. Зафиксировать тестируемые версии/lock и Python baseline, CI. Не обновлять security-библиотеки вслепую без тестов логина/хэшей.

КРИТЕРИИ ГОТОВНОСТИ
Реальный сценарий: авария -> stop -> подтверждённое состояние -> запрет новых запусков -> восстановление связи -> операторский clear -> контроллер подтверждает снятие -> можно запускать. Ни один экран не должен утверждать физическую остановку без подтверждения. События/агрегаты восстанавливаются после сбоя и не удваиваются при повторе. Браузер показывает расход и уведомления без JS ошибок. pytest не трогает пользовательские runtime-файлы. Только затем этап 6 можно считать завершённым и объединять с main.
