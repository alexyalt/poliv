# AGENTS.md — обязательные правила работы в проекте «Полив»

> Этот файл — системный промпт для ИИ-ассистента (Qwen Coder и пр.).
> **Читать в начале КАЖДОЙ рабочей сессии, до выполнения любой задачи пользователя.**

## 1. WorkBook — журнал истории (ОБЯЗАТЕЛЬНО)

Ведётся в папке `WorkBook/`:

- `WorkBook/WORKBOOK.md` — главный непрерывный журнал всей истории проекта;
- при разрастании (> ~800 строк) — ротация: старый контент переносится в `WorkBook/WORKBOOK_архив_<период>.md`, в основном файле остаётся актуальная часть + ссылки на архивы.

**Правило исполнения:** каждое содержательное изменение в проекте (код, миграции, конфигурация, документация, решения, отклонения от плана) автоматически фиксируется записию в `WORKBOOK.md` **в той же сессии, что и само изменение**, без напоминания пользователя. Запись добавляется в конец файла как новый блок. Пустяковые правки (опечатка в комментарии) можно объединять в одну запись с ближайшим изменением.

Формат записи:

```
## [ДД.ММ.ГГГГ] <Этап/N> — <краткая тема>
- **Контекст/запрос:** что требовалось (со ссылкой на раздел ТЗ Этапа 0 / ADR / файл комментариев).
- **Что сделано:** фактические изменения (файлы, коммиты).
- **Соответствие плану Этапа 0:** точно по плану / расширено / сокращено.
- **Отклонения и их причины:** …
- **Принятые решения (ADR-N или новые):** …
- **Новые функции/подходы вне первоначального плана:** …
- **Статус проверки:** автотесты (N passed), ручная проверка, push (хеш).
```

Ссылочные данные брать из первоисточников: ТЗ — `stage0/Этап 0 Полное ТЗ с артефактами.txt` (разделы «Этап N», Артефакт 0.2 — реестр ADR), комментарии — `docs/commets_for_satges/`, инструкции — `docs/ИНСТРУКЦИЯ_ЭТАП*.md`.

## 2. Порядок работы над этапами

1. Перед началом этапа перечитать раздел ТЗ этого этапа и реестр ADR.
2. Реализация → автотесты (`python -m pytest server/tests -v`, все зелёные) → инструкция ручной проверки в `docs/ИНСТРУКЦИЯ_ЭТАП<N>.md` → после подтверждения пользователем — push в `main`.
3. Комментарии пользователя к этапу сохраняются в `docs/commets_for_satges/` и обрабатываются полностью либо явно заносятся в WORKBOOK как «отложено» с причиной.

## 3. Технические конвенции проекта

- FastAPI + Jinja2 MPA, без сборщиков (ADR-07); SQLite (WAL) — единственная БД (ADR-03, ADR-08).
- Зоны и контроллеры не удаляются физически — только отключение (`deleted_at`) согласно ТЗ Этапа 2.
- Параллелизм зон — только явным `parallel_group` (ADR-12); по умолчанию последовательно (ADR-05).
- Новый синтаксис `TemplateResponse(request, name, context)` (Starlette 1.0+).
- Секретов в коде нет; локальные файлы (`data/`, `logs/`, `config.local.toml`, `.venv`) не коммитить — контролируется `.gitignore`.
- Коммиты и push — по запросу пользователя; пуш только после прохождения автотестов.
