# Миграция 0002_stage2_catalogs

## Зачем

Этап 2 ТЗ: «Базовые справочники и CRUD». Нужны таблицы для управления
контроллерами, зонами, программами, пользователями и настройками.

## Что делает

1. **programs** — программы полива:
   - `schedule_type`: `weekdays` (дни недели) или `interval` (интервал в днях);
   - `weekdays_mask` — 7 символов пн..вс; `interval_days` — для интервала;
   - `start_time` HH:MM; сезонность `season_start/season_end` (MM-DD);
   - `enabled` — включение/отключение.
2. **program_zones** — привязка зон к программе с порядком `seq` (1..).
   Программа может быть без зон и содержать зоны разных контроллеров
   (ограничений на контроллер нет). При удалении программы связи каскадно
   удаляются (`ON DELETE CASCADE`) — сама программа удаляется физически,
   т.к. история исполнения появится на Этапе 4.
3. **zone_locks** — блокировки зон (ручной полив, обслуживание). На Этапе 2
   только таблица; логику постановки/снятия блокировок подключим на Этапах 4–5.
4. **ALTER controllers**: `model`, `deleted_at` (soft-disable).
   **ALTER zones**: `deleted_at` (soft-disable), `season_start`, `season_end`.
5. **settings**: ключи корректировок полива со значениями по умолчанию
   (`adjustment.*`). Значения редактируются администратором из UI.

## Правила целостности

- Зоны и контроллеры не удаляются физически: `deleted_at IS NOT NULL` означает
  «удалено» (soft-disable). Сервисный слой фильтрует такие записи.
- `UNIQUE(controller_id, zone_number)` из миграции 0001 сохраняется: номер
  зоны уникален в пределах контроллера и не переиспользуется даже после
  soft-удаления — это защита от «наследия» старых расписаний.
- В одной программе зона встречается один раз: `UNIQUE(program_id, zone_id)`.

## Откат

SQLite не поддерживает обратные ALTER для ADD COLUMN до версии 3.35;
миграции проекта применяются последовательно и откат не предусмотрен
(перед эксперименты — копия БД в backups/).
