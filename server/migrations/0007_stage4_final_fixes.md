# Миграция 0007_stage4_final_fixes

Закрывает блокирующие замечания аудитора №2 к Этапу 4 перед Этапом 5 (UI машинограмм + журнал полива).

## Что добавляет

| Таблица | Назначение | Замечание |
|---|---|---|
| `pending_schedule` | Очередь отложенной доставки машинограмм (P1-2). При `send_schedule` во время активного прогона (`apply_policy=next_run`) новая версия сохраняется со статусом `queued`; хук в `on_event` при `finished`/`stopped` отправляет последнюю queued-версию. Состояние переживает перезапуск сервера (БД, не память). | P1-2 |
| `schedule_compile_errors` | Ошибки автокомпиляции после CRUD программ/зон/настроек (P1-3). Настройки применяются, но ошибка (например, конфликт запусков) сохраняется и возвращается API (422 с деталями), чтобы UI различал «настройки сохранены» и «расписание применено». | P1-3 |
| `schedule_rejections` | История отказов контроллера `schedule_ack status=rejected` (P1-5) с причиной; при отказе `controllers.schedule_version` НЕ меняется. | P1-5 |

## Статусы pending_schedule
- `queued` — ожидает завершения активного прогона;
- `sent` — отправлена после освобождения (или немедленно);
- `cancelled` — вытеснена более новой queued-версией того же контроллера;
- `failed` — отправка не удалась (MQTT недоступен).

## Совместимость
Применённые миграции 0001–0006 не изменяются (правило AGENTS.md). Идемпотентно (`CREATE TABLE IF NOT EXISTS`).
