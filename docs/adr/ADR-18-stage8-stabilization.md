# ADR-18 — стабилизация этапа 8 (8.S)

Дата: 26.10.2026. База: e026ee4b890c677ded9ab726b43c7caa497a5204.
Дополняет ТЗ этапа 0 и ADR-14. Исходные записи WorkBook и ТЗ сохраняются.

## Контракты

- Предпросмотр одного погодного правила получает явный набор правил в памяти. Глобальный флаг и enabled правила не меняются. Выключенное правило можно проверить гипотетически; weather.enabled и политика свежести данных продолжают действовать. Другие правила не участвуют в этом тесте.
- Sync/async команды используют общий исполнитель. Обычные команды упорядочены по box_id. `stop_all` обходит ожидание ACK, повышает поколение остановки и запрещает дальнейшие публикации/повторы ранее принятых обычных команд. Уже доставленную команду отозвать невозможно: контроллер обязан выполнить stop и дедупликацию command_id. Поздний ACK не является доказательством физического положения клапана.
- Отчёт по зоне использует факт finished/stopped event; run.volume_liters используется только без такого факта. Для run-only многозонного запуска общий объём делится поровну как оценка. Точная атрибуция параллельных event-зон требует отдельного согласованного алгоритма; текущие сохранённые данные не переписываются.

## Архив v2

Вместо дописываемого общего файла — неизменяемая партия
`<data_dir>/<archive.path>/<entity>/YYYY-MM-DD_<uuid>.csv|json` и соседний
`<filename>.manifest.json`. Абсолютный archive.path остаётся абсолютным.
Новая миграция 0011 добавляет format_version и manifest_hash к журналу;
старые строки получают version=1, новые — 2. file_hash относится ко всему
неизменяемому основному файлу, manifest_hash — ко всему manifest.

Manifest содержит schema_version, batch_id, entity_type, file_hash, row_count,
запрошенную дату, перечни NULL-полей каждой строки и watering_event_zones.
CSV сохраняет прежние основные колонки, JSON — массив родителей. Нельзя
резервировать/переносить основной файл без manifest и журнала БД.

Ротация использует отдельное соединение и BEGIN IMMEDIATE до выборки.
Это сериализует ротацию между потоками и процессами SQLite. Данные и manifest
пишутся во временные файлы, fsync, atomic rename; на POSIX синхронизируются
каталоги. Только затем удаляются выбранные родители/дети и вставляется журнал
в той же транзакции. DELETE разбит на партии по 500 ID.

Протокол восстановления после сбоя:

1. Нет зарегистрированной строки archive_exports — исходные данные остаются
   в БД после rollback. Файл .tmp или готовая незарегистрированная партия —
   дополнительная копия, а не разрешение на импорт/удаление данных.
2. Зарегистрированная v2-партия — оба файла должны существовать и совпадать
   с хешами. Повреждение отклоняется до вставок.
3. Если файлы записаны, а commit не прошёл, повтор создаёт новую уникальную
   партию. Автоматически импортировать/удалять orphan-файлы запрещено.
   Для их удаления оператор сначала сверяет журнал и исходные данные с копией.
4. Restore выполняется транзакционно, сохраняет NULL и связи. Совпадающие
   записи пропускаются; конфликт ID с другими данными завершает rollback,
   не скрывается INSERT OR IGNORE.

Существующие legacy-файлы и пути в журнале не перемещаются. Для них невозможно
доказать полноту дочерних связей/первоначальных NULL и проверить старый хеш
всего дописываемого файла; ответ restore содержит legacy_incomplete=true.
Повреждённые legacy JSON-массивы не конвертируются автоматически. До любого
ручного исправления нужны копия и проверка парсером.

Restore flow/weather по-прежнему явно не реализован. Архив не заменяет backup
пользователей, конфигурации и активных расписаний. WAL-БД копировать через
SQLite backup API или при корректно остановленном приложении.

## Совместимость и эксплуатация

HTTP/MQTT пути, поля команд, command_id, QoS и запрет retain/offline-запуска
сохранены. Изменён только файловый контракт новых архивов; старый тест append
заменён тестом неизменяемости по этому ADR, остальные ожидания не ослабляются.
Запускать один процесс Uvicorn до полной координации фоновых singleton.
Ротация пока удерживает write transaction во время записи файлов: это сознательная
гарантия целостности, а оптимизация fetchall и длительности lock остаётся отдельной
задачей. Ошибка/таймаут записи сохраняет источник в БД.

Новый auth middleware не пускает пользователя с временным паролем в обычные
страницы/API до собственной смены через /account/password. Logout/login/health
доступны. При смене отзываются остальные сессии. Secure cookie включается на
HTTPS или server.cookie_secure=true. Origin/Referer проверяются для изменяющих
запросов; отсутствие этих заголовков допустимо для существующих API клиентов,
но Sec-Fetch-Site: cross-site отклоняется. При reverse proxy нужны доверенные
forwarded headers, иначе same-origin будет оценён неверно.

## Остатки, которые нельзя считать закрытыми

Полный переход auth/catalog/event/flow/notification на соединение на запрос или
worker (F07), SQL/heatmap оптимизации, устойчивый processed-event ledger после
архивации, точная многозонная атрибуция, missed-report и недельная приёмка UI,
нагрузка, реальный Mosquitto и ESP32. Новая фабрика соединений обеспечивает
foreign_keys/busy_timeout, но сама по себе не изолирует старые общие conn.
См. current-status.md; новые 9A/9B не объявляются выполненными.
