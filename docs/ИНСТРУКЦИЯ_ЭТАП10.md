# Этап 10 — сборка и стендовая проверка ESP32

## Сборка

Требуется PlatformIO. Секреты не коммитятся:

```sh
cp firmware/include/secrets.example.h firmware/include/secrets.h
# заполнить Wi-Fi/MQTT, оставить OUTPUTS_VERIFIED=false до проверки стенда
pio run -d firmware -e esp32dev
pio test -d firmware -e native
```

Образ использует `partitions.csv`: два OTA app-раздела по 1600 КиБ, `nvs`, `otadata` и `storage`. Flash-образ перед прошивкой сравнивать с лимитом раздела.

## Безопасная последовательность стенда

1. Отключить насос и подачу воды. Подключить только ESP32 и 74HC595.
2. Прошить с `OUTPUTS_VERIFIED=false`. Проверить, что все выходы закрыты после boot, MQTT disconnect, ошибки flash и watchdog.
3. Подать команды `zone_open` с этим флагом: команда должна быть отклонена.
4. В режиме без воды разрешить `OUTPUTS_VERIFIED=true`, проверить порядок 1..16 и активный уровень реле мультиметром/светодиодом.
5. Подключить один клапан без давления. Проверить `zone_open`, `zone_close`, `stop_all`, `pause_controller`, `resume_controller`, duplicate `command_id`.
6. Для расписания проверить `water -> soak -> water`, поздний запуск, неверный hash/version, смену расписания во время прогона.
7. При включённом расходомере проверить `no_flow` после 10 секунд открытия и `unexpected_flow` при закрытых клапанах.
8. Обесточить контроллер во время шага и проверить поведение согласно `RESUME_AFTER_POWER_LOSS`. По умолчанию продолжение запрещено: активный run пропускается и клапаны остаются закрытыми.
9. Проверить в MQTT: `hello`, `status`, `lwt`, `schedule_ack`, `command_ack`, `event`, `flow`, `schedule_request`.

Аппаратная приёмка не считается выполненной без этого прогона. Пин-карта: Data GPIO13, Clock GPIO12, Latch GPIO14, опциональный расходомер GPIO27. Полярность реле на референсной плате должна быть подтверждена отдельно.
