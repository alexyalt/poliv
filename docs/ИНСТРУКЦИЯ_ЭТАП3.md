# Инструкция по проверке Этапа 3 (Базовый MQTT и эмулятор контроллеров)

Тестирование выполняется на машине с Windows. Команды — для `cmd.exe`
(для PowerShell пути аналогичны, разделитель `;`). Версия приложения: `0.3.0+<hash>`
(видна в шапке страниц и в выводе сервера при старте).

Границы этапа (не проверяем): компиляция машинограмм и расписания — Этап 4;
операторский интерфейс — Этап 5; хранение событий/аварий в БД — Этап 6
(события пишутся только в `logs/mqtt.log` и журнал действий source=mqtt).

## 2. Установка и настройка брокера Mosquitto

### Windows
1. Скачать установщик с https://mosquitto.org/download/ (или `winget install EclipseFoundation.Mosquitto`).
2. Установить (по умолчанию `C:\Program Files\mosquitto`). Сервис запускается автоматически;
   для ручной проверки можно запускать из консоли (см. п. 2.3).

### Linux (Debian/Ubuntu)
```bash
sudo apt update && sudo apt install -y mosquitto mosquitto-clients
```

### 2.1 Конфигурация
Скопировать пример конфига в рабочий:
```bat
copy config\mosquitto.conf.example C:\progra~1\mosquitto\poliv.conf
```
Содержимое (кратко): `listener 1883`, `allow_anonymous false`, `password_file ...`.

### 2.2 Пользователи брокера (парольная файл-база)
Логин сервера — `poliv_server` (из `[mqtt] username` в config.default.toml).
Логины контроллеров = их Box ID (например `BOX-EMUL-01`).

```bat
cd "C:\Program Files\mosquitto"
mosquitto_passwd -c passwords poliv_server      :: -c создаёт файл (первый раз)
mosquitto_passwd passwords BOX-EMUL-01          :: добавить ещё пользователя
mosquitto_passwd passwords BOX-EMUL-02
```
Linux: `sudo mosquitto_passwd -c /etc/mosquitto/passwd poliv_server` и т.д.

### 2.3 Запуск брокера
```bat
:: Windows (ручной режим, консоль видна)
"C:\Program Files\mosquitto\mosquitto.exe" -c C:\progra~1\mosquitto\poliv.conf -v
:: Linux
mosquitto -c /etc/mosquitto/poliv.conf -v
```
**Ожидаемый результат:** в консоли `mosquitto version ... running`, слушает порт 1883.

### 2.4 Секреты сервера
Пароль MQTT сервера хранится ТОЛЬКО в локальном конфиге (в git не попадает):
```bat
copy config\config.local.toml.example config\config.local.toml
```
В `config\config.local.toml` заполнить `[mqtt] password="..."` (тот же пароль,
что задан для `poliv_server` в mosquitto_passwd) и `secret_key`.

| API live | GET /api/controllers/{id}/live и /api/controllers/live — view-модель Артефакта 0.6 §4.5 |

## 4. Ручной сценарий (брокер → сервер → эмулятор → команда → офлайн → возврат)

### 4.1 Запуск
```bat
:: Терминал 1 — брокер (см. п. 2.3)
:: Терминал 2 — сервер:
.venv\Scripts\python.exe server\main.py
:: Терминал 3 — эмулятор одного контроллера:
.venv\Scripts\python.exe emulator\controller_sim.py --box-id BOX-EMUL-01 ^
    --user BOX-EMUL-01 --password <его_пароль> --status-interval 5 --zones 16
```
Эмулятор должен быть создан как контроллер в БД с тем же Box ID
(страница «Контроллеры», Этап 2) — тогда hello сопоставит box_id и плитку оживут.

Парк из N контроллеров:
```bat
.venv\Scripts\python.exe emulator\fleet_sim.py --count 3 --user-prefix BOX-EMUL- --password <пароль>
```
(создаст/использует BOX-EMUL-01..03; имена вида `BOX-EMUL-xx`).

Открыть http://127.0.0.1:8000, войти admin или оператором.

### 4.2 Чек-лист (выполнить по порядку)

1. **hello → online.** Через ≤10 с после старта эмулятора плитка BOX-EMUL-01:
   badge «online», поля mode/phase/active_zones/last_seen обновляются каждые ~5 с
   (JS-опрос `/api/controllers/live`). → в `logs\mqtt.log` строка hello.
2. **time-синхронизация.** В логе эмулятора — приём `poliv/BOX-EMUL-01/time`
   и расхождение с локальным временем (сервер отвечает при hello и раз в 6 ч).
3. **schedule_request.** При старте эмулятор шлёт запрос; получает заглушку
   `schedule_version=0, runs=[]` и пишет schedule_ack. → в `logs\mqtt.log`.
4. **Команда zone_open.** На плитке: зона=1, длительность=60 → «Открыть зону».
   → flash «zone_open: отправлена (command_id=...)»; в эмуляторе ack accepted→completed,
   mode=watering, active_zones=[1], flow-сообщения каждые 10 с, событие полива
   (start/stop) в `logs\mqtt.log`; на дашборде видно зону 1.
5. **zone_close / stop_all / pause / resume.** Повторить кнопки → состояние
   эмулятора меняется, ack completed, журнал команд (command.sent/command.acked).
6. **Идемпотентность.** Вручную повторить команду с тем же command_id нельзя из UI
   (uuid4 каждый раз); проверка на уровне сервиса: дублирующий ack игнорируется (тест),
   а эмулятор на повторный command_id отвечает `ignored_duplicate` без действия
   (можно проверить через `mosquitto_pub` в topic command дважды с одним command_id).
7. **Офлайн по LWT.** В терминале эмулятора нажать `o` (или завершить процесс Ctrl+C).
   → плитка стала «offline» почти мгновенно (retained lwt online=false).
8. **Офлайн по порогу.** Альтернатива: запустить эмулятор с `--offline-after 20`
   и временно уменьшить `offline_threshold_min` — через минуту фонового опроса
   статусов плитка offline (source: threshold). Подробная методика — §4.3 ниже.
9. **Команда offline-контроллеру.** Нажать кнопку на offline-плитке
   (или POST /api/controllers/{id}/actions/ping). → отказ «controller_offline» (409),
   в `logs\mqtt.log` публикаций команды нет, факт в журнале.
10. **Возврат онлайн.** Снова `o` в эмуляторе (или перезапуск) → hello → online,
    last_hello_at/firmware обновились.
11. **Авария.** Клавиша `e` в эмуляторе → mode=error, error_code=4001 на плитке;
    клавиша `w` → ручной полив зоны 1 на 60 с (flow + события). По завершении
    прогона в `logs\mqtt.log` обязано появиться finished-событие с `source`
    (`manual`) — регресс покрыт тестом `test_emulator_fixes.py`.
12. **Роли.** Войти viewer: кнопок команд нет, POST actions → 403. Оператор: 202.
    reboot доступен только admin (viewer/operator → 403).
13. **Невалидная JSON-строка.** Проверить нельзя из UI; подтверждается автотестом
    (битый payload → warning, сервер жив).
14. **Heartbeat.** `mosquitto_sub -h 127.0.0.1 -u poliv_server -P <пароль> -t poliv/server/heartbeat -v`
    → retained-сообщение каждые 30 с.
15. **Перезапуск сервера.** Ctrl+C, старт заново → миграция 0004 применена однократно
    (в `.db` колонки live-state есть), повторных ошибок нет.

### 4.3 Методика «офлайн по порогу» (пункт 8 чек-листа)

Проверяет, что сервер сам переводит контроллер в offline, если давно нет
сообщений о состоянии (source: threshold), даже без воли брокера.

1. В `config\config.local.toml` временно уменьшить порог до 1 минуты:
   ```toml
   [mqtt]
   offline_threshold_min = 1
   ```
2. Перезапустить сервер (конфиг читается при старте).
3. Запустить эмулятор с имитацией обрыва через 20 секунд:
   `python emulator\controller_sim.py --offline-after 20`
   (в fleet-режиме тот же флаг пробрасывается всем:
   `python emulator\fleet_sim.py --count 3 --offline-after 20`).
4. Через ~20 с — обрыв связи (в логе эмулятора «ОФЛАЙН (имитация обрыва
   связи)»). Сервер увидит offline по порогу не позднее чем через ~60 с
   после обрыва (фоновый опрос + `offline_threshold_min=1`); в журнале —
   событие `controller.offline_threshold`, плитка — badge «offline».
5. Проверка завершена: **вернуть `offline_threshold_min = 30`** и перезапустить
   сервер (иначе тестовая среда будет «пилить» статусы слишком часто).

Примечание: штатное завершение эмулятора (Ctrl+C / клавиша `o`) теперь само
публикует retained-LWT (`online=false`, reason `shutdown`/`lwt-sim`) перед
disconnect — брокер при корректном разрыве волю НЕ выдаёт, без этой имитации
офлайн по порогу был бы единственным способом увидеть потерю связи.

## 5. Критерии приёмки Этапа 3 (DoD)

- [ ] `pytest server\tests -q` — все зелёные (регресс Этапов 1–2 включён);
- [ ] дашборд показывает плитки со статусами эмулятора: online/offline, mode, phase,
      active_zones, last_seen (обновление ≤10 с);
- [ ] команда zone_open уходит на брокер, эмулятор открывает зону, сервер получает
      ack accepted→completed (журнал command.sent/command.acked);
- [ ] разрыв эмулятора (клавиша `o` / `--offline-after`) виден как offline
      (LWT сразу или по порогу offline_threshold_min);
- [ ] повтор команды с тем же command_id эмулятором не выполняет действие повторно
      (ack ignored_duplicate);
- [ ] offline-контроллер: действия возвращают 409 controller_offline, публикаций нет;
- [ ] невалидный JSON в status/event не роняет сервер (warning в logs/mqtt.log);
- [ ] schedule_request получает заглушку schedule_version=0 (компиляция — Этап 4);
- [ ] пароли MQTT только в config.local.toml; в коммите нет data/, logs/, *.pyc,
      .venv, config/config.local.toml;
- [ ] версия приложения 0.3.0+<git hash>.
