# Инструкция по проверке Этапа 5 (Операторский интерфейс)

Тестирование выполняется на машине с Windows. Команды — для `cmd.exe`
(для PowerShell пути аналогичны, разделитель `;`). Версия приложения: `0.5.0+<hash>`
(видна в шапке страниц и в выводе сервера при старте; хэш должен соответствовать
последнему коммиту `main`).

Границы этапа (не проверяем): хранение событий/аварий в БД и расчёт расхода по
фактическим данным — Этап 6; must_change_password и CSRF/Secure-cookie — отложены;
WebSocket-обновление не делается по ТЗ (опрос каждые 10 секунд — п.5 Этапа 5).

Что проверяется:
- дашборд (главная страница `/`): плитки контроллеров со статусом, активной зоной,
  остатком времени, последним контактом, объёмом за сегодня и ошибками (ТЗ п.1);
- страница контроллера `/controllers/{id}`: live-состояние, зоны с активностью,
  история прогонов, управление командами (ТЗ п.2);
- view-API: `GET /api/dashboard-view` и `GET /api/controllers/{id}/view` — готовые
  для отображения данные, фронтенд не пересчитывает timestamps сам;
- опрос данных фронтендом каждые 10 секунд (polling, без WebSocket — ТЗ п.5);
- адаптация интерфейса под телефон (критерий готовности ТЗ).

---

## 1. Подготовка окружения (однократно)

```bat
cd C:\poliv
git pull
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
```

**Ожидаемый результат:** зависимости установились без конфликтов версий.

Если проверка Этапа 5 выполняется сразу после Этапов 3–4, окружение брокера
Mosquitto и эмуляторов уже настроено (см. `docs\ИНСТРУКЦИЯ_ЭТАП3.md`, §1–2) —
повторно настраивать не нужно. Иначе — выполните §1–2 инструкции Этапа 3
(установка Mosquitto, пользователи `poliv_server` и `BOX-EMUL-xx`, пароль в
`config\config.local.toml`).

## 3. Ручная проверка — минимальный контур (без брокера)

Подходит для быстрой проверки страниц и view-API, когда эмулятор не запускается.

Запуск сервера:
```bat
.venv\Scripts\python.exe server\main.py
```
Открыть http://127.0.0.1:8000, войти как `admin` (пароль — из `logs\app.log`
при первом запуске).

1. **Дашборд.** Главная страница отдаёт 200; сводка «Контроллеров / Онлайн /
   Поливают сейчас / Сегодня» отображается; у тестового контроллера (если включён
   `[test_data]`) — плитка со статусом offline и ошибкой «Нет связи с контроллером».
2. **View-API.** В новой вкладке: http://127.0.0.1:8000/api/dashboard-view → JSON
   с полями `summary`, `controllers[]`, `server_now_ts`.
3. **Страница контроллера.** Клик «Открыть →» на плитке (или `/controllers/<id>`) →
   страница с разделами: live-таблица, «Зоны», кнопки управления, история прогонов.
4. **Без сессии.** Выйти (или открыть приватное окно) → `/` и `/controllers/1`
   редиректят на `/login`; `/api/dashboard-view` → 401 JSON.

Далее — полный сценарий с живыми данными (§4).

## 4. Ручная проверка — полный сценарий (брокер + эмулятор)

### 4.1 Запуск (три терминала)

```bat
:: Терминал 1 — брокер (настройка — ИНСТРУКЦИЯ_ЭТАП3.md §2)
"C:\Program Files\mosquitto\mosquitto.exe" -c C:\progra~1\mosquitto\poliv.conf -v

:: Терминал 2 — сервер:
.venv\Scripts\python.exe server\main.py

:: Терминал 3 — эмулятор контроллера (должен быть создан в БД с тем же Box ID,
:: страница «Контроллеры»; расход зон задаётся в карточках зон — см. п.4):
.venv\Scripts\python.exe emulator\controller_sim.py --box-id BOX-EMUL-01 ^
    --user BOX-EMUL-01 --password <его_пароль> --status-interval 5 --zones 16
```

Парк из N контроллеров (для многоплиточного дашборда):
```bat
.venv\Scripts\python.exe emulator\fleet_sim.py --count 3 --user-prefix BOX-EMUL- --password <пароль>
```

Открыть http://127.0.0.1:8000, войти admin или оператором.

### 4.2 Чек-лист (выполнить по порядку)

1. **hello → онлайн-плитка.** Через ≤10 с после старта эмулятора плитка
   BOX-EMUL-01: badge «online», режим/фаза, «Виден» обновляется (статусы шлются
   каждые ~5 с, страница перерисовывается опросом раз в 10 с).
2. **Автообновление без F5.** Не перезагружая страницу, дождаться смены значений
   в плитке (например, после п.4). В DevTools → Network каждые 10 с виден запрос
   `GET /api/dashboard-view` (200, JSON). Это контракт ТЗ п.5 (polling, без WebSocket).
3. **Сводка.** В блоке «Сводка»: Контроллеров ≥1, Онлайн ≥1, «Поливают сейчас»
   меняется вместе с состоянием эмулятора.
4. **Расход для литров.** Заранее (или сейчас) на странице «Зоны» задать зонам
   1 и 2 контроллера `expected_flow_lpm` (например 12 и 6 л/мин). Без заданного
   расхода графа «Полив за сегодня» остаётся «—» (данных для пересчёта нет — это
   ожидаемое поведение Этапа 5; фактический расход — Этап 6).
5. **Ручной запуск полива.** На плитке: зона=1, длительность=60 → «Открыть зону».
   → flash «zone_open: отправлена (command_id=…)»; через ≤10 с плитка: режим
   watering, активная зона №1, «Остаток фазы» убывает (~60 → 0), сводка
   «Поливают сейчас» = 1.
6. **Видно, что поливается (критерий приёмки).** Во время полива открыть
   `/api/dashboard-view`: у плитки `active_zone=1`, `phase_remaining_sec` и
   `run_remaining_sec` положительны и уменьшаются от опроса к опросу;
   `summary.watering_now >= 1`.
7. **Остановить (критерий приёмки).** Нажать «Стоп» на плитке. → через ≤10 с
   mode=idle, активная зона «—», ошибок нет; в истории на странице контроллера
   прогон получил статус completed/aborted.
8. **Объём за сегодня.** После завершённого прогона зоны 1 (60 с при 12 л/мин)
   в плитке «Полив за сегодня» ≈ 12 л (60·12/60); в `/api/dashboard-view` —
   `watered_today_liters` и `summary.today.runs` соответствуют. Повторный прогон
   зоны 2 (6 л/мин, 60 с) добавит ≈ 6 л (итог ≈ 18 л). Литры считаются по
   локальному дню сервера; плановые (не начавшиеся) прогоны не в зачёте.
9. **Страница контроллера (критерий приёмки).** «Открыть →» с плитки →
   `/controllers/{id}`: live-таблица (статус, режим, фаза, активная зона,
   остатки), таблица «Зоны» (номер, название, расход, активность), кнопки
   zone_open/zone_close/стоп/пауза, «История прогонов» (план→факт, зоны,
   длительность). Запустить полив кнопкой со страницы — строка активной зоны
   подсвечивается, «Остаток» убывает; обновление — опрос
   `/api/controllers/{id}/view` каждые 10 с (видно в DevTools).
10. **Команда офлайн-контроллеру.** В терминале эмулятора нажать `o` (offline).
    → плитка badge «offline», в ошибках плитки «Нет связи с контроллером».
    Нажать любую кнопку команды → отказ (409 controller_offline / сообщение об
    ошибке), публикаций в логе брокера нет. Снова `o` (возврат) → hello → online.
11. **Ошибка времени.** Эмулятор, не получивший синхронизацию времени
    (time_valid=0), показывает на плитке ошибку «Время контроллера не
    синхронизировано» (после старта обычно проходит быстро — фиксировать, если
    видите).
12. **Ошибки расписания на плитке.** Если у контроллера есть ошибка компиляции
    (см. ИНСТРУКЦИЯ_ЭТАП4.md) или машинограмма в очереди — на плитке в списке
    ошибок появляются строки «Расписание: …» / «Машинограмма в очереди на
    отправку (N)»; подробности — на странице контроллера (блоки compile_error /
    pending_schedules).
13. **Роли.** Войти `viewer`: кнопок команд нет (только просмотр), POST напрямую
    → редирект с ошибкой «Действие доступно оператору или админу»; оба view-API
    отвечают 200 (читать можно всем авторизованным). Войти `operator`: команды
    доступны.
14. **Баннер потери связи с сервером.** Остановить сервер (Ctrl+C в терминале 2),
    оставить открытую страницу дашборда. Через ~10–20 с появляется баннер
    «⚠ Нет связи с сервером — данные ниже могли устареть». Перезапустить сервер →
    баннер исчезает, плитки снова обновляются.
15. **Адаптация под телефон (критерий приёмки).** В Chrome нажать F12 → иконка
    устройства (или Ctrl+Shift+M), ширина 375 px (iPhone). Дашборд: сетка плиток
    складывается в одну колонку, кнопки читаемы, ничего не вылезает за экран.
    То же на странице контроллера и `/login`. Дополнительно — открыть
    http://<локальный IP машины>:8000 с реального телефона в той же сети.
16. **Перезапуск сервера.** Ctrl+C, старт заново → страницы открываются, данные
    целы (миграции не применяются повторно), «Полив за сегодня» продолжает
    считаться по прогонам дня.

## 5. Критерии приёмки Этапа 5 (DoD)

- [ ] `pytest server\tests -q` — все зелёные (регресс Этапов 1–4 включён,
      `test_stage5.py` — 13 passed);
- [ ] видно, что сейчас поливается: активная зона + остаток времени на плитке
      и странице контроллера, сводка «Поливают сейчас» (чек-лист пп.5–6);
- [ ] можно остановить: кнопка «Стоп» гасит полив ≤10 с (п.7);
- [ ] можно запустить вручную: zone_open с дашборда/страницы контроллера (пп.5, 9);
- [ ] можно открыть страницу контроллера: live + зоны + история + управление (п.9);
- [ ] интерфейс адаптируется под телефон (п.15);
- [ ] объём за сегодня считается по watering_runs × expected_flow_lpm, плановые
      прогоны не в зачёте (п.8);
- [ ] ошибки (офлайн, рассинхрон времени, компиляция/очередь) видны на плитке (пп.10–12);
- [ ] опрос каждые 10 секунд, без WebSocket; повторные опросы идемпотентны (п.2);
- [ ] viewer читает view-API, команды — только operator+ (п.13);
- [ ] версия приложения `0.5.0+<git hash>` в шапке страниц.
