# Монитор и погодный прогноз: проверка и настройки

Ветка `feature/weather-monitor` включает все предшествующие изменения этапов 10–11.
Базовая версия приложения остаётся 0.11.0, commit в заголовке уточняет сборку.
Перед обновлением остановите сервер и выполните backup по основной инструкции.
Миграции 0014/0015 применяются автоматически; пользовательские координаты сохраняются.
Пустые координаты получают 44.423062, 34.06452.

## Монитор

1. Откройте `/`. На широком мониторе по умолчанию четыре колонки.
2. Первые плитки — аварии, затем потеря связи, предупреждения и работающие контроллеры.
   Цвет дополнен текстом: статус виден без различения цветов. Аварии имеют контрастную
   красную рамку, offline — серый фон, полив — голубой, пауза — жёлтая метка.
   Мигающей анимации и звука нет.
3. Сводка показывает количество контроллеров, полив, аварии и потерю связи.
   «Только проблемы» скрывает исправные плитки; «На весь экран» скрывает навигацию.
   Для постоянного экрана используйте отдельную учётную запись viewer и продумайте
   session_timeout_min; fullscreen не отменяет истечение сессии.
4. На плитке: название, зона, измеренный поток. Скрытые/неизвестные измерения — «—».
   Поток нескольких зон — общий поток контроллера, не выдуманная разбивка по зонам.
5. Нажмите плитку для подробностей; кнопки отдельно отправляют команды. Старт —
   ручной полив зоны с указанием времени, а не запуск всего расписания. На паузе
   Старт означает resume. При ошибке/потере связи диалог закрывается после poll.
6. На `/active-zones` нет offline/ошибочных/service/приостановленных зон. Это список
   полученного состояния, не физическая гарантия открытого клапана.
7. Отключите сервер: banner устаревания и блокировка кнопок. После восстановления
   следующий poll возвращает рабочее состояние. Last update — получение UI, не
   timestamp физического измерения. Offline устройства определяется серверным LWT/timeout.

## Прогноз

1. Откройте `/weather`. Прогноз загружается из сохранённого snapshot, не делает
   внешний запрос при каждом открытии. Фоновый updater обновляет его с погодным
   интервалом, оператор/администратор может нажать «Обновить прогноз».
2. «24 часа»: текущий час и следующие 23 в часовом поясе прогноза. Графики:
   температура, осадки и вероятность, ветер/порывы, влажность, VPD, температура
   поверхности почвы. Направление ветра и влажность верхнего слоя почвы — в таблице.
3. «7 дней»: текущие локальные сутки и следующие шесть. Минимум/максимум температуры,
   сумма осадков/максимальная вероятность, максимум ветра/порывов, ET₀ и UV.
4. Ветер — м/с, осадки/ET₀ — мм, VPD — кПа. Вероятность на осадковом графике имеет
   отдельную шкалу 0…100%. Указатель на точку показывает точное значение; таблица
   доступна отдельно. Пропущенные значения рисуются разрывами, не нулями.
5. Краткая строка: диапазон температуры/осадки/порывы за 24ч, ET₀ за 7 дней.
   ET₀ не равен потребности конкретного растения: нужны коэффициент культуры,
   тип почвы, корневая зона, эффективность системы и реальные осадки.
6. Рекомендации: заморозок, жара, сильный ветер, заметные осадки, высокий VPD.
   Пороги настраиваются. VPD >1.6 кПа — общий ориентир возможного стресса,
   чувствительность зависит от культуры. Почва — модель, а не датчик участка.
7. Snapshot старше трёх часов или неполный явно помечается. Рекомендации по старому
   snapshot подписаны как устаревшие. Без данных нельзя трактовать отсутствие
   предупреждений как отсутствие риска. Изменение координат требует нового snapshot:
   данные прежней точки не показываются для новой.
8. Существующие правила автоматической коррекции находятся в раскрывающемся блоке
   ниже. Новые подсказки не меняют нормы полива, блокировки или расписания.

Проверенный живой запрос: Open-Meteo вернул HTTP 200, Europe/Simferopol, ветер в m/s,
температуру в °C, VPD в kPa, moisture в m³/m³. Запрос включал forecast_days=8, чтобы
получить запас по часам; интерфейс ограничивает вывод 24 часами / 7 днями.
Данные/атрибуция: https://open-meteo.com/ и https://open-meteo.com/en/docs .

## Доступные настройки

В `/settings` параметры сгруппированы; погода и монитор раскрыты, остальные группы
свёрнуты. Viewer видит значения без редактирования, сохраняет только admin.
Все значения формы предварительно проверяются до начала записи.

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| weather.latitude / longitude | 44.423062 / 34.06452 | Точка прогноза |
| weather.wind_warning_ms | 8 м/с | Предупреждение по порывам |
| weather.frost_warning_c | 2 °C | Риск заморозка |
| weather.heat_warning_c | 32 °C | Жара |
| weather.rain_warning_mm | 5 мм | Осадки за 24 часа |
| weather.update_interval_min | 60 мин | Получение погоды |
| dashboard.columns | 4 | Колонки широкого монитора, 2…8 |
| dashboard.refresh_sec | 5 сек | Опрос плиток, 3…60 |
| dashboard.pause_minutes | 60 мин | Пауза кнопкой, 1…1440 |
| dashboard.manual_seconds | 60 сек | Начальная длительность, 1…3600 |

После изменения настроек монитора перезагрузите открытые страницы. На меньших
экранах число колонок автоматически сокращается. Частота polling не меняет
период отправки MQTT status самой платой. Настройки сертификатов и пароли остаются
в локальном конфиге/USB, их нельзя переносить в обычные настройки UI.

## Проведённые проверки

- Полный pytest, миграции/авторизация/правила/архив и восстановление.
- Chromium: настоящий FastAPI/SQLite с тестовым состоянием 50 контроллеров,
  действия start/pause/stop, диалог, переход к деталям, priority/filter/fullscreen,
  offline/recovery, viewer, 390/768/1366/1920 px.
- Погода: 24ч/7д, ручное обновление, таблицы, null и stale, смена координат,
  отсутствие чужого snapshot, readonly/валидация настроек.
- Существующие browser smoke: heatmap, отчёты, блокировки, proposal/apply/ACK.
- Mosquitto: ACK/retry/stop/replay и TLS/CA/hostname/password/ACL.
- Native/ESP32 build: совместимость envelope сервера без box_id в теле.

Это проверки в Chromium; Safari/Firefox, длительный kiosk soak, доступность
screen reader и полевые испытания не подменяются этими результатами.
