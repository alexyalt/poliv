# ИНСТРУКЦИЯ — ЭТАП 8: отчёты, архив и тепловая карта

Версия приложения: **0.8.0**. Цель этапа: базовая аналитика (отчёты по зонам,
контроллерам, дням, месяцам, программам, авариям) с выгрузкой CSV; файловый
архив с ротацией оперативной БД (ADR-14: бесконечный архив в `data/archive/`,
БД — ограниченный срез `archive.db_retention_days`); тепловая карта полива за
сутки (интервалы 5/10/15/30 мин, состояния idle/water/soak/manual/blocked/
error/offline, раскрытие контроллеров в зоны).

---

## 1. Подготовка окружения

1. Миграция 0010 применится автоматически при старте сервера (загрузчик
   миграций из `server/app/infra/db.py` подхватит файл по имени): создаёт
   таблицу `archive_exports` (журнал выгрузок) и настройки `archive.*`
   (`enabled=true`, `db_retention_days=365`, `path="archive"`,
   `events_format="csv"`). Идемпотентна и обратима (`downgrade`).

   ```bat
   python -m server.migrations.0010_archive
   ```

2. Запустите MQTT-брокер и сервер (как на Этапах 3–7):

   ```bat
   mosquitto -c mosquitto.conf
   python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
   ```

   В lifespan вместе с WeatherUpdater стартует `ArchiveDaemon` — daemon-поток,
   который раз в сутки в 03:00 локального времени вызывает `rotate_all()`
   (ошибка одного типа сущностей не роняет цикл; `archive.enabled=false`
   полностью отключает ротацию).

3. Данные для проверки можно взять существующие (Этапы 4–7) или сгенерировать
   прогон/события через эмулятор либо прямой INSERT в `watering_runs` /
   `watering_events`.

## 3. Ручная проверка

### 3.1. Отчёты

1. Войдите под viewer → меню → «Отчёты» (`/reports`).
2. Выберите пресет диапазона (сегодня / неделя / месяц / квартал / год) или
   явные даты `from`/`to`; переключите вкладки: Зоны | Контроллеры | Дни |
   Месяцы | Программы | Аварии.
3. Убедитесь, что агрегаты соответствуют фактическим прогонам (число прогонов,
   минуты, литры, пропуски, аварии). При пустой БД — пустая таблица, без ошибки.
4. Нажмите «Экспорт CSV» — файл `report_<вид>_<from>_<to>.csv` скачивается с
   корректными заголовками (стабильны даже при пустом результате).
5. Через API (например, curl/браузер с сессией):

   ```
   GET /api/v1/reports/zones?from=2026-09-01&to=2026-09-30
   GET /api/v1/reports/incidents?preset=month&limit=50&offset=0
   GET /api/v1/reports/days.csv?preset=year
   ```

   Некорректная дата → 422; без входа → 401; viewer/operator/admin — читают.

### 3.2. Архив

1. Проверьте журнал: `GET /api/v1/archive/config` и
   `GET /api/v1/archive/exports` (viewer+).
2. Сухая проба ротации (ничего не пишет/не удаляет):

   ```
   POST /api/v1/archive/rotate
   {"entity_type": "events", "target_date": "2025-10-20", "dry_run": true}
   ```

   (под operator; без `entity_type` — все типы сразу).
3. Боевая ротация той же пачки:

   ```
   POST /api/v1/archive/rotate
   {"entity_type": "events", "target_date": "2025-10-20"}
   ```

   Ожидаемо: файл `data/archive/events/ГГГГ-ММ-ДД.csv` (дата дня выгрузки),
   строки удалены из `watering_events` (+ каскад `watering_event_zones`),
   в `archive_exports` появилась запись с `row_count` и sha256.
4. Повторный rotate за ту же дату — идемпотентен (0 строк, файл/журнал не
   растут). Штатный ночной проделывает то же самое `ArchiveDaemon` в 03:00.
5. Настройки можно менять в таблице `settings` (`archive.db_retention_days`,
   `archive.events_format = csv|json`, `archive.path`).

### 3.3. Тепловая карта

1. Меню → «Тепловая карта» (`/heatmap`). Выберите дату и интервал
   (5/10/15/30 мин).
2. Убедитесь: Y — контроллеры, X — время; клик по контроллеру раскрывает его
   в строки зон; цвета соответствуют легенде (idle/water/soak/manual/blocked/
   error/offline); в подсказке ячейки — контроллер, зона, программа, фаза,
   расход за слот.
3. API: `GET /api/v1/heatmap?date=2026-10-26&interval_min=15` (viewer+);
   параметр `controller_ids=1,2` фильтрует строки; битые параметры → 422.
4. При пустой БД отдаётся сетка целиком из `idle` (или пустая при отсутствии
   контроллеров) — без ошибок.

## 4. Критерии готовности (DoD)

- [x] Можно посмотреть отчёт по зонам / контроллерам / дням / месяцам /
      программам / авариям за выбранный диапазон (пресеты + явные даты).
- [x] Факт полива виден в отчётах (runs_count, total_minutes, total_liters —
      из watering_runs/watering_events; аварии — из событий и notifications).
- [x] Любой отчёт выгружается в CSV (`/api/v1/reports/<вид>.csv`, кнопка
      «Экспорт CSV»; формулы экранированы общей утилитой `infra/csv_export`).
- [x] Архив пишется в файлы по дням: `data/archive/{entity_type}/YYYY-MM-DD.csv`
      (json — для events при `archive.events_format=json`); журнал —
      `archive_exports`; фоновая ротация в 03:00; ручная — через API.
- [x] Тепловая карта открывается, раскрывает контроллеры в зоны, показывает
      состояния ячеек с подсказками.
- [x] Интерфейс не тормозит на 50 контроллерах × 16 зонах × 96 слотах
      (сервисная сборка < 500 мс — автотест).
- [x] Регресс не сломан: 219 passed, 1 skipped; сервер стартует без ошибок.
