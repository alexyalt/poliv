# Пошаговая проверка на компьютере и ESP32

Версия 0.11.0. Ветка `feature/stage11-dashboards` включает прошивку этапа 10.
Первые части выполняются без платы. Основной воспроизводимый сценарий — Ubuntu 24.04 / Debian с Python 3.13, Mosquitto 2 и ESP32-DevKit 4 МБ. На Windows сервер/брокер можно запустить в WSL2, USB-прошивку — из Windows PlatformIO. Для доступа ESP32 к WSL2 нужна отдельная настройка проброса LAN-порта; проще разместить брокер на Linux-хосте или в Windows с LAN listener. Эта инструкция не предполагает, что плата уже проверена.

## 1. Получить код и изолировать данные

На тестовой Linux-машине:

```sh
git clone https://github.com/alexyalt/poliv.git
cd poliv
git switch feature/stage11-dashboards
python3.13 -m venv .venv
. .venv/bin/activate
pip install -q -r requirements.lock
mkdir -p "$HOME/poliv-runtime"
export POLIV_DATA_ROOT="$HOME/poliv-runtime"
export POLIV_CONFIG_LOCAL="$HOME/poliv.local.toml"
python -c 'import secrets; print(secrets.token_hex(32))'
```

Сохраните полученный ключ в следующем конфиге. Не используйте существующую боевую БД для первого теста. Если обновляете прежнюю установку, остановите сервер и сначала перенесите данные командой `python -m server.tools.prepare_runtime --destination /новый/путь` (каталог назначения не должен существовать); затем укажите этот путь в POLIV_DATA_ROOT. Нельзя одновременно запускать два сервера над одной БД. На Windows PowerShell переменные задаются как `$env:POLIV_DATA_ROOT="C:\poliv-runtime"` и `$env:POLIV_CONFIG_LOCAL="C:\poliv.local.toml"`.

## 2. Настроить брокер и индивидуальные права

```sh
sudo apt-get install mosquitto mosquitto-clients
python -m server.tools.broker_config --destination "$HOME/poliv-broker-generated" --box TESTBOX-0001 --box 5B2338
sudo install -m 644 "$HOME/poliv-broker-generated/poliv.conf" /etc/mosquitto/conf.d/poliv.conf
sudo install -m 640 -o root -g mosquitto "$HOME/poliv-broker-generated/poliv.acl" /etc/mosquitto/poliv.acl
sudo mosquitto_passwd -c /etc/mosquitto/poliv.passwd poliv_server
sudo mosquitto_passwd /etc/mosquitto/poliv.passwd box_TESTBOX-0001
sudo mosquitto_passwd /etc/mosquitto/poliv.passwd box_5B2338
sudo chown root:mosquitto /etc/mosquitto/poliv.passwd
sudo chmod 640 /etc/mosquitto/poliv.passwd
sudo systemctl restart mosquitto
sudo systemctl status mosquitto
```

`-c` создаёт новый файл паролей: применяйте его только при первой установке! Для существующей установки добавляйте пользователей без `-c`. Если уже есть listener 1883, используйте одну согласованную конфигурацию, не два listener на одном порту. Генератор не перезаписывает существующий каталог. Для других box_id добавьте `--box ID` и создайте пользователя `box_ID`.

Порт 1883 — только доверенная локальная сеть; аутентификация/ACL не шифруют трафик. Не публикуйте его в интернет. Серверу нужен TCP 1883, ESP32 — LAN-адрес компьютера, а не 127.0.0.1. Разрешите входящий TCP 1883/8080 только из своей подсети. TLS/публичное размещение и защищённая OTA ещё не приняты.

## 3. Создать локальный конфиг сервера

Создайте файл по пути POLIV_CONFIG_LOCAL:

```toml
[server]
secret_key = "ВСТАВЬТЕ_СГЕНЕРИРОВАННЫЙ_КЛЮЧ"
cookie_secure = false
[admin]
username = "admin"
password = "ВЫБЕРИТЕ_ДЛИННЫЙ_ПАРОЛЬ"
must_change_password = true
[test_data]
enabled = true
box_id = "TESTBOX-0001"
[mqtt]
host = "127.0.0.1"
port = 1883
username = "poliv_server"
password = "ПАРОЛЬ_ИЗ_MOSQUITTO_PASSWD"
```

На Linux: `chmod 600 "$POLIV_CONFIG_LOCAL"`. При первом входе смените пароль администратора; изменение bootstrap-пароля в конфиге не сбрасывает уже созданную учётную запись.

## 4. Запустить и проверить сервер без платы

```sh
python -m uvicorn server.main:app --host 0.0.0.0 --port 8080 --workers 1
```

1. Откройте `http://127.0.0.1:8080`, войдите и смените начальный пароль.
2. В другом терминале активируйте venv и те же переменные окружения.
3. Запустите эмулятор:

```sh
python -m emulator.controller_sim --box-id TESTBOX-0001 --broker 127.0.0.1 --port 1883 --user box_TESTBOX-0001 --password ПАРОЛЬ_ЭМУЛЯТОРА --status-interval 5
```

Пароль в параметре процесса эмулятора виден локальным пользователям: используйте отдельную тестовую учётную запись. Ожидается online на плитке. Если нет: проверьте журналы Mosquitto, box_id, ACL, логин и пароль. Нельзя одновременно запускать эмулятор и ESP32 с одним box_id.

## 5. Проверить оба дашборда

1. Откройте `/`: плитка показывает имя контроллера, статус, работающую зону и поток.
2. Нажмите «Старт», выберите зону и 30 секунд. Это ручной запуск, не запуск всего расписания.
3. Проверьте синий статус «Полив» и появление зоны на `/active-zones` в течение 5–10 секунд.
4. Если расходомер отключён или измерение неизвестно, поток — «—», а не выдуманный ноль. При параллельных зонах подпись уточняет, что поток общий для контроллера.
5. «Пауза» останавливает полив на час. «Старт» на жёлтой плитке возобновляет работу. «Стоп» прерывает текущий прогон.
6. Нажмите основную область плитки: откроются подробности контроллера. Кнопки не должны открывать настройки.
7. Остановите эмулятор: статус станет «Нет связи» после LWT/таймаута. Устаревшая зона не должна оставаться на дашборде активных зон.
8. Остановите сервер при открытой странице: появится сообщение об устаревших данных, управление будет заблокировано.
9. Войдите как viewer: плитки доступны без кнопок. Как operator: доступны старт/пауза/стоп. Проверьте страницу на телефоне.

## 6. Проверить расписания и историю без платы

1. В справочнике зон задайте имена и длительность; создайте программу с ближайшим временем старта и одной зоной на 1 минуту.
2. В разделе расписаний выполните preview/compile и отправку. Дождитесь ACK, не считайте «отправлено» подтверждением применения.
3. Проверьте `water → soak → water` при включённом cycle/soak и блокировку зоны через существующий экран блокировок.
4. Сверьте события, журнал и отчёт: факты должны появляться после событий контроллера.
5. Отключите сеть эмулятора/брокер и восстановите связь; проверьте повторную регистрацию и отсутствие второго действия на duplicate command_id.

## 7. Собрать и подключить ESP32, когда плата будет доступна

```sh
pip install -q platformio==6.2.0
cp firmware/include/secrets.example.h firmware/include/secrets.h
pio test -d firmware -e native
pio run -d firmware -e esp32dev
```

В secrets.h задайте WIFI_SSID/WIFI_PASSWORD, MQTT_HOST=LAN-адрес компьютера, MQTT_USER=`box_5B2338`, MQTT_PASSWORD. Проверьте настоящий MAC: box_id автоматически получается из последних трёх байтов. Для другой платы создайте её box_id в справочнике и ACL. Оставьте OUTPUTS_VERIFIED=false, FLOW_ENABLED=false, RESUME_AFTER_POWER_LOSS=false.

1. Отключите насос, воду и силовое питание клапанов. Подключите плату USB.
2. Сохраните имеющуюся прошивку платы отдельным инструментом esptool перед первой перезаписью, если нужен возврат к ней.
3. Прошейте: `pio run -d firmware -e esp32dev -t upload` (при необходимости `--upload-port /dev/ttyUSB0`, Windows `COM3`).
4. Откройте `pio device monitor -d firmware -b 115200`.
5. На пустой flash может быть storage_error. Только при первой инициализации без нужных данных отправьте `FORMAT` и перевод строки. Это стирает LittleFS. При повторной эксплуатации FORMAT не нужен.
6. Добавьте реальный контроллер и зоны в UI. Проверьте hello, online, прошивку и service. Ручной старт пока должен отклоняться.
7. При ошибке flash/fault, оставшейся после форматирования, проверьте журнал; сохранённую аварийную блокировку снимайте `clear_error` только после устранения причины. storage_error может потребовать перезапуска после исправления хранилища.

## 8. Проверить реле и полив

1. Без воды и насоса проверьте GPIO13 Data, GPIO12 Clock, GPIO14 Latch, питание и общую землю.
2. Выясните полярность реле и соответствие каналов 1…16. Выставьте RELAY_ACTIVE_HIGH. Включите OUTPUTS_VERIFIED=true только для проверки без нагрузки и пересоберите.
3. Проверяйте каналы по одному короткими командами. Ни в какой момент два реле не должны быть включены. Проверьте все 16, boot/reset и потерю USB.
4. Для реальной платы выключите parallel_enabled на сервере: многозонное расписание прошивка отклоняет.
5. Подключите один клапан и короткий полив, затем «Пауза», «Старт», «Стоп»; сверяйте физический клапан, две страницы, MQTT ACK и события.
6. При отключённом расходомере FLOW_ENABLED=false. Для датчика включите его, проверьте GPIO27/уровни и откалибруйте FLOW_PULSES_PER_LITER по известному объёму.
7. Проверьте no_flow при отсутствии импульсов после открытия и unexpected_flow при импульсах с закрытым клапаном. Авария должна закрывать все выходы; после устранения причины снимите аварийную блокировку.
8. Проверьте автономность: сначала синхронизируйте время и примените расписание, затем отключите сервер/сеть. Расписание должно исполняться локально. Холодный старт без валидного времени запрещает автоматический полив.
9. Обесточьте в середине шага. По умолчанию активный run пропускается. Опциональный resume может повторить до 5 секунд с последнего checkpoint; включать его только после оценки на стенде.
10. Повторите несколько циклов и проверьте историю после восстановления связи. Ограничения QoS1/питания изложены в ADR-20.

## 9. Резервная копия и восстановление

При остановленном сервере и из корня checkout:

```sh
python -m server.tools.runtime_snapshot backup --source "$POLIV_DATA_ROOT" --destination "$HOME/poliv-backup-001"
python -m server.tools.runtime_snapshot verify --source "$HOME/poliv-backup-001"
python -m server.tools.runtime_snapshot restore --source "$HOME/poliv-backup-001" --destination "$HOME/poliv-restored-001"
```

Назначение не должно существовать. Инструмент сохраняет источник, проверяет SHA-256 файлов, SQLite integrity и foreign keys, переносит пути расписаний/архивов. Ссылки вне runtime требуют отдельной копии: инструмент откажется считать такой backup полным. Отдельно сохраните конфиг сервера, secrets.h, MQTT passwd/ACL и код нужной версии в защищённом месте. SHA-256 обнаруживает повреждение, но не является подписью.

Для контрольного восстановления остановите сервер, укажите POLIV_DATA_ROOT на восстановленный каталог и запустите его той же версией кода. Сверьте пользователей, зоны, расписания, историю и файлы архивов. Не подключайте одновременно оригинал и восстановленный сервер к одним физическим контроллерам.

## 10. Автозапуск на Linux

`deploy/poliv.service` предполагает код в /opt/poliv, venv в /opt/poliv/.venv, пользователя poliv, runtime /var/lib/poliv и конфиг /etc/poliv/config.local.toml. Подготовьте эти пути и права (runtime принадлежит poliv, конфиг 640 root:poliv). Код и venv должны читаться пользователем poliv. Скопируйте unit в /etc/systemd/system, выполните `sudo systemctl daemon-reload`, `sudo systemctl enable --now poliv`. Проверьте `systemctl status poliv` и `journalctl -u poliv`. Выполните перезагрузку компьютера и повторный вход в UI.

Перед backup/restore: `sudo systemctl stop poliv`; после проверки запускайте `sudo systemctl start poliv`. Не запускайте uvicorn вручную одновременно со службой.

## 11. Зафиксировать результаты

Запишите версию/commit, ОС, MAC/box_id, полярность, датчик/калибровку и результат каждого шага. Приложите журналы с удалёнными паролями. Аппаратная приёмка сейчас не проведена; OTA-загрузка/rollback, DS3231, физическая failsafe-кнопка и пилот на 50 платах ещё не готовы. Обновление прошивки в этой версии выполняется по USB.
