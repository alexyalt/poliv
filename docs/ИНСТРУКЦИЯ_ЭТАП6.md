# ИНСТРУКЦИЯ — ЭТАП 6: события полива, контроль расхода, уведомления

Версия приложения: **0.6.0**. Цель этапа: фиксировать фактические события
полива (start/stop/finish), принимать телеметрию расхода (flow), детектировать
аварии (`no_flow`, `over_flow`), вести суточную агрегацию литров и генерировать
уведомления с звуковой сигнализацией на странице `/events`.

---

## 1. Подготовка окружения

1. Убедитесь, что применена миграция 0008 (таблицы `watering_events`,
   `flow_daily`, `notifications`; настройки `flow.*` и `ui.sound_notifications_enabled`):

   ```bat
   python -m server.migrations.0008_stage6_events_flow_notifications
   ```

   (либо миграция применится автоматически при старте сервера).

2. Запустите MQTT-брокер (Mosquitto, как на Этапе 3) и сервер:

   ```bat
   mosquitto -c mosquitto.conf
   python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
   ```

3. Запустите эмулятор контроллера (он публикует `poliv/<box>/flow` и
   `poliv/<box>/event` — см. `emulator/controller_sim.py`):

   ```bat
   python -m emulator.controller_sim --box BOX-W1
   ```

## 3. Ручная проверка (полный контур с брокером)

Чек-лист:

1. Откройте `http://localhost:8000/events` (логин operator/admin).
2. Скомандуйте открытие зоны (`POST /api/controllers/{box}/zone-open`) —
   в течение ~10 с на странице появится событие `started` и живые samples
   расхода (л/мин, суммарные литры).
3. Дождитесь окончания полива — событие `finished` с фактически излитыми
   литрами; в блоке «Сводка за день» вырастет `total_liters`.
4. Авария `no_flow`: остановите подачу воды в эмуляторе (или уберите
   `expected_flow_lpm`) — в течение окна `flow.no_flow_grace_s` должно
   появиться critical-уведомление «нет протока», блок поливов до
   `flow.block_until`, звук beep на странице.
5. Авария `over_flow`: завысьте расход выше `flow.over_flow_factor` —
   warning/critical-уведомление, событие не теряется (дубликаты по
   `event_uid` отбрасываются UNIQUE-индексом).
6. Колокольчик/счётчик: `GET /api/notifications/unread-count` возвращает
   `unread_count`, `max_unread_critical_id`, `sound_enabled`; после
   `POST /api/notifications/{id}/read` счётчик уменьшается,
   `POST /api/notifications/read-all` обнуляет.
7. Экспорт: `GET /api/events/export.csv?from=...&to=...` отдаёт CSV.
8. Просмотр viewer: читает `/events` и API, но не может отмечать прочитанным
   через operator-маршруты (403) — сверьте с матрицей ACL.
9. Перезапуск сервера: данные событий/уведомлений сохраняются в БД,
   live-flow восстанавливается из статусов/потока контроллера.
