# Запуск из вашего каталога с кириллицей и пробелами

Проект: `C:\Users\Зам. директора\Downloads\КОНТРОЛЛЕР\proj\poliv`.
Скрипты определяют папку проекта по собственному расположению; переносить проект
или редактировать пути внутри скрипта не требуется. PowerShell-файлы оставлены
ASCII-совместимыми для Windows PowerShell 5.1. setup.json читается как UTF-8.

При запуске без `-Runtime` используется соседний каталог
`C:\Users\Зам. директора\Downloads\КОНТРОЛЛЕР\proj\poliv-runtime`.
Он должен быть подготовлен один раз. Если runtime уже создан в другом месте,
передавайте его прежний путь через `-Runtime` — повторно создавать его не нужно.

```powershell
Set-Location -LiteralPath 'C:\Users\Зам. директора\Downloads\КОНТРОЛЛЕР\proj\poliv'
py -3.13 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -q -r requirements.lock
# Только если runtime ещё НЕ создан; IP замените адресом компьютера из ipconfig:
& '.\.venv\Scripts\python.exe' -m server.tools.windows_setup --runtime '..\poliv-runtime' --host 192.168.1.20 --box 5B2338
# Этап без контроллера:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\windows\Test-Poliv.ps1' -Stage software
# Позже, после подготовки ESP32:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\windows\Test-Poliv.ps1' -Stage controller
```

Все пути с пробелами заключайте в кавычки. Для другого checkout можно указать
`-ProjectRoot 'D:\Другой каталог\poliv'`. Это необязательный параметр.
Ниже сохранены подробности этапов и примеры с явно указанным runtime:
если вы выбрали соседний `poliv-runtime`, используйте его вместо `C:\PolivLab\runtime-001`.

# Windows: интерактивное тестирование и отчёт

Мастер запускает отдельные процессы Mosquitto/сервера, выполняет HTTP-проверки,
предлагает автоматические Chromium-сценарии и задаёт обязательные вопросы.
Два независимых этапа: `software` без платы и `controller` с ESP32.
Ответы и автопроверки сохраняются после каждого шага в report.json и report.md.

## 1. Подготовить компьютер один раз

### Если `py -3.13` не найден

Сообщение `No suitable Python runtime found` означает, что Python ещё не установлен.
Установите его через PowerShell:

```powershell
winget install --id Python.Python.3.13 --exact --scope user
```

Если `winget` недоступен, скачайте Python 3.13 x64 с https://www.python.org/downloads/windows/.
В установщике включите **Install launcher for all users** и **Add python.exe to PATH**.
После установки полностью закройте PowerShell и откройте новое окно. Проверьте:

```powershell
py -3.13 --version
```

Ожидается `Python 3.13.x`. Только после этого запускайте `Test-Poliv.ps1`; он сам
создаст `.venv`. Если `.venv` не появилась после неудачной попытки, это нормально:
повторный запуск создаст её после установки Python.

1. Установите Git, Python 3.13 x64 с `py` launcher и Mosquitto 2.x для Windows.
2. Скачайте main в `C:\PolivLab\poliv` (или git clone). Для ZIP нужны все файлы,
   включая scripts/server/firmware. Без .git в отчёте будет «unknown commit».
3. Откройте PowerShell и перейдите в проект:

```powershell
Set-Location -LiteralPath 'C:\Users\Зам. директора\Downloads\КОНТРОЛЛЕР\proj\poliv'
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -q -r requirements.lock
.\.venv\Scripts\python.exe -m server.tools.windows_setup --runtime C:\PolivLab\runtime-001 --host 192.168.1.20 --box 5B2338
```

Замените IP на IPv4 Windows из ipconfig, box_id на реальный ID платы. Каталог
runtime-001 не должен существовать. Мастер настройки попросит пароли admin,
server MQTT и платы. Повторный запрос mosquitto_passwd для poliv_server — тот же
серверный MQTT-пароль. Полная инструкция: WINDOWS_SETUP.md, шаги 0–2.
Пароли не пишите в ответы тестового опроса. Runtime содержит секретный конфиг:
дайте доступ только своей Windows-учётной записи и администраторам.

4. Остановите установленную службу Mosquitto, если занимает 1883. Закройте ранее
   запущенные окна Poliv. Мастер откажется запускаться на занятых 1883/8080,
   не станет останавливать чужие процессы. Разрешите TCP1883 в Firewall только
   Private/LocalSubnet по WINDOWS_SETUP.md. UI доступен только на localhost.
5. При первой проверке сервер ещё без пользователей. Мастер откроет браузер,
   где нужно войти admin и сменить начальный пароль, затем ввести новый пароль
   в скрытом запросе консоли. Он не сохраняется в report.

## 2. Этап без контроллера

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Test-Poliv.ps1 -Runtime C:\PolivLab\runtime-001 -Stage software
```

Скрипт сам проверит/создаст `.venv`, добавит её Scripts в PATH своего процесса,
установит locked зависимости и запустит мастер. Системную policy он не меняет.
Не требуется Activate.ps1; используется Python именно из папки проекта.
Интернет нужен для установки пакетов и загрузки Chromium/погоды.

Последовательность:

1. Согласие оператора, запуск брокера и проверка MQTT auth.
2. Запуск локального сервера, ожидание HTTP, открытие браузера.
3. Вход через консоль текущим admin/operator после смены начального пароля.
4. Автопроверки страниц /, active-zones, weather, settings и API.
5. По вашему «да» установка Chromium и UI-сценарии на отдельной временной БД:
   50 тестовых плиток, ошибки, offline, weather и reset. Эти сценарии не
   подключаются к физической плате и не используют её данные.
6. Вопросы по реальному браузеру: читаемость, погода, settings, отдельный viewer.
   Если viewer не создан или сценарий не проверен, ответьте «пропустить».
7. Развернутые замечания и итог. Мастер остановит только собственный сервер/брокер.

Вопросы `да/нет/пропустить` принимают именно эти слова, неверный ответ запрашивается
повторно. Числовой ответ >=0, дробный разделитель точка или запятая. Развёрнутый ответ
может занимать несколько строк; **отдельная строка с точкой** завершает ввод.
Пустой ответ не принимается; допускается «не проверено» с причиной.

## 3. Этап с ESP32

Сначала подготовьте USB/COM, service firmware и профиль Wi-Fi/MQTT по WINDOWS_SETUP.md,
шаги 4–6. Мастер **не прошивает и не меняет полярность платы**. Не запускайте одновременно
эмулятор с тем же box_id. Перед тестом закройте вручную запущенные сервер/брокер.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Test-Poliv.ps1 -Runtime C:\PolivLab\runtime-001 -Stage controller
```

1. Запуск сервисов/вход аналогично первому этапу. Создайте контроллер и зоны в UI,
   если их ещё нет. В консоли выберите ID из списка, запишите COM/полярность/датчик.
2. Мастер запросит **новое согласие на физические действия**. Без «да» команды
   не отправляются, этап отмечается пропущенным. Насос должен быть отключён,
   давления нет, выходы проверены без нагрузки.
3. Выберите зону 1…16. Каждая команда отдельно требует «да»: старт на 10 секунд,
   пауза 60 секунд, resume. После каждой подтвердите физический результат.
   В service firmware открытие отклоняется — это ожидаемо до проверки полярности.
4. При завершении/прерывании сценария мастер пытается STOP. Если сеть недоступна,
   в отчёте FAIL: физически отключите питание нагрузки, не доверяйте одному UI.
   Ctrl+C не является аппаратной аварийной кнопкой. Принудительное закрытие окна,
   выключение ПК или зависание ОС не гарантируют доставку STOP.
5. Запишите измеренную задержку закрытия. Если не измеряли — прервите опрос,
   не вводите выдуманный ноль. Расписание, power-cut, flow/reset проверяются
   вручную по подсказкам и матрице W01–W16 в WINDOWS_SETUP.md.
6. Завершите опрос подробными замечаниями. Не выполняйте reset/потерю питания
   под давлением без безопасного стенда. Без датчика flow — «пропустить».

## 4. Прерывание и продолжение

Ctrl+C сохраняет `interrupted` и останавливает собственные процессы. В консоли
показывается каталог отчёта, например:
`C:\PolivLab\runtime-001\test-reports\20261029-120000-a1b2c3`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Test-Poliv.ps1 -Runtime C:\PolivLab\runtime-001 -Stage software -Resume 'C:\PolivLab\runtime-001\test-reports\20261029-120000-a1b2c3'
```

Этап Resume должен совпадать с исходным. Сохранённые ответы переиспользуются,
автопроверки повторяются. Для платы выбор контроллера и разрешения на действия
спрашиваются заново; нельзя автоматически воспроизводить старое согласие.
Повторные ответы сохраняются в хронологии. Новый независимый прогон — без Resume.

## 5. Отчёт для анализа

В `runtime\test-reports\<run>`:

- `report.md` — читаемый отчёт: ОС/Python/commit, PASS/FAIL, время и ответы.
- `report.json` — структурированные данные для дальнейшего анализа.
- `server.log`, `broker.log`, при автосценариях `automation.log` — журналы.

completed означает завершение опроса, не отсутствие FAIL и не допуск к воде.
failed/interrupted — незавершённый прогон; ответы остаются. Просмотрите отчёт,
приложите фотографии/снимки отдельно и проверьте журналы на секреты. Не отправляйте
целиком config.local.toml, secrets.h, broker passwd или весь runtime.
Рекомендуется передавать report.md + report.json и очищенные относящиеся к сбою логи.

## 6. Критерии

Без платы: HTTP/MQTT PASS, UI читаем, нет неожиданных ошибок, settings сохраняются,
viewer не управляет. С платой: физический порядок зон/полярность подтверждены,
нет самопроизвольного старта, один клапан за раз, stop по времени/команде,
честный offline/ACK/reset, сохранность после перезагрузки. Непроверенные сценарии
явно отмечены. OTA/rollback и аппаратная приёмка остаются ограничениями: STATUS.md.
