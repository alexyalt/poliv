# Инструкция: что делать с кодом Этапа 1, как проверять и критерии успешности

## 1. Что это за код (структура)

| Путь | Назначение |
|---|---|
| `server/main.py` | Точка входа сервера. Порядок старта: конфиг → логирование → БД + миграции → создание администратора → тестовые данные → веб-маршруты |
| `server/app/infra/config.py` | Загрузка TOML-конфигурации (`config/config.default.toml` + переопределения в `config/config.local.toml`) с проверкой целостности |
| `server/app/infra/db.py` | SQLite (WAL, внешние ключи), простой механизм миграций |
| `server/migrations/0001_initial.py` | Первая схема БД: users, sessions, logs, settings, controllers, zones |
| `server/app/services/auth_service.py` | Авторизация: bcrypt-хэши, сессии, ограничение попыток входа, журнал действий |
| `server/app/services/test_data.py` | Тестовый контроллер и зоны для разработки |
| `server/app/web/routes.py`, `templates/`, `static/` | Веб-интерфейс: вход, выход, дашборд, страницы ошибок 403/404/500 |
| `server/tests/test_stage1.py` | Смоук-тесты критериев готовности Этапа 1 |
| `logs/` | Файловые логи с ротацией (app.log, errors.log) |
| `data/` | Файл базы данных SQLite |

## 2. Что делать с этим кодом (установка и запуск)

```bash
# 1. Установить зависимости (обязательно в виртуальном окружении)
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2. Настроить локальный конфиг при необходимости
#    config/config.local.toml — пароли/порты не должны попадать в git
#    admin_password = ""  => пароль будет сгенерирован и выведен в лог один раз

# 3. Прогнать тесты
python -m pytest server/tests -q

# 4. Запустить сервер
python server/main.py
# или: python -m uvicorn server.main:app --host 0.0.0.0 --port 8080

# 5. Открыть в браузере http://localhost:8080/login
#    Логин: admin; пароль — из лога logs/app.log (строка "Пароль администратора ...")
```

## 3. Как проверять и что именно проверять

### 3.1 Автоматическая проверка (смоук-тесты)
```bash
python -m pytest server/tests -q
```
Проверяют: `/health` отвечает `status: ok`; без сессии `/` делает redirect на `/login`; корректный логин пускает на дашборд; неверный пароль отклоняется; создаются файл БД и лог-файлы.

### 3.2 Ручная проверка (чек-лист)
Открыть в браузере / выполнить curl:

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `GET /health` | `200`, JSON `{"status":"ok","stage":1}` |
| 2 | `GET /` без входа | `302` redirect на `/login` |
| 3 | `GET /login` | `200`, форма входа отображается со стилем |
| 4 | Вход `admin` + пароль из `logs/app.log` | `200`, дашборд с тестовым контроллером и зонами |
| 5 | Вход с неверным паролем | `401`, сообщение об ошибке; после серии неверных попыток — блокировка (rate limit) |
| 6 | Выход (logout) | редирект на `/login`, повторный доступ к `/` требует входа |
| 7 | `GET /nesushchestvet` | страница ошибки 404 |
| 8 | Первый старт с пустой БД | в `logs/app.log`: «Создан первый администратор» и сгенерированный пароль (WARNING) |
| 9 | Повторный старт | новый пароль НЕ генерируется, вход работает тем же паролем (БД сохранена) |
| 10 | Файлы | существуют `data/*.db` (SQLite, режим WAL), `logs/app.log`, `logs/errors.log`; ротация логов настроена |
| 11 | Конфиг | правка `config/config.local.toml` (например, порт) применяется без правки default; битый TOML даёт понятную ошибку при старте |

## 4. Критерии успешности Этапа 1 (Definition of Done)

- [ ] Зависимости ставятся одной командой `pip install -r requirements.txt` без конфликтов версий.
- [ ] Все смоук-тесты проходят: `pytest server/tests` → **все зелёные**.
- [ ] Сервер запускается без ошибок и переживает перезапуск (данные сохраняются в SQLite).
- [ ] Конфигурация разделена: общие значения в `config.default.toml`, секреты/локальные — в `config.local.toml` (не в git); целостность проверяется при старте.
- [ ] Миграция `0001_initial` применяется автоматически; таблицы users/sessions/logs/settings/controllers/zones созданы.
- [ ] Работает авторизация: хэширование bcrypt, сессии, rate-limiting неудачных входов, запись действий в журнал.
- [ ] Логирование в файлы с ротацией; ошибки отдельно в `errors.log`.
- [ ] Веб-страницы: вход, дашборд, выход, 403/404/500 отображаются корректно.
- [ ] Загружены тестовые данные: минимум 1 контроллер и набор зон видны на дашборде.
- [ ] README/доки содержат инструкции по запуску.

## 5. Известные проблемы и исправления (актуально на момент написания)

1. **passlib ↔ bcrypt**: установлен `bcrypt>=4.0,<4.1` (в `requirements.txt` закреплено). Версии 4.1+/5.x ломают `passlib.hash.bcrypt` — повышать нельзя до замены passlib на прямой `bcrypt`.
2. **pytest 9**: в окружении был pytest 9.1.1, который падал на загрузке плагина `libtmux` («Marks cannot be applied to fixtures»). В `requirements.txt` закреплено `pytest>=8.0,<9`; на pytest 8.x тесты проходят (2 passed).
3. **Адрес health-эндпоинта**: он смонтирован как `GET /health` (не `/api/health`).
4. Мелкое предупреждение FastAPI: устаревший способ вызова `TemplateResponse(name, {"request": ...})` — стоит обновить синтаксис на этапах 2–3.
