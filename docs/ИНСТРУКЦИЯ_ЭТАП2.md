# Инструкция по проверке Этапа 2 (Базовые справочники и CRUD)

Тестирование выполняется на машине с Windows. Команды — для `cmd.exe` (для PowerShell пути аналогичны, разделитель `;`).

---

## 1. Подготовка окружения (однократно)

```bat
cd C:\poliv
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
```

**Ожидаемый результат:** зависимости установились без конфликтов версий (bcrypt <4.1, pytest <9).

## 3. Ручная проверка

Запуск сервера:
```bat
.venv\Scripts\python.exe server\main.py
```
Открыть http://127.0.0.1:8000 — войти как `admin` (пароль: первый вход — из `logs\app.log`, либо тот, что задан при ручном тесте Этапа 1).

### Чек-лист (выполнить по порядку)

1. **Навигация.** В шапке появились пункты: Контроллеры, Зоны, Программы, Настройки; «Пользователи» виден только админу. → страницы открываются без ошибок.
2. **Контроллеры — создание.** Добавить контроллер (название, тип, Box ID). → появляется в списке; запись в журнале действий.
3. **Контроллеры — дубль Box ID.** Повторно создать с тем же Box ID (регистр/пробелы иные). → ошибка валидации на русском, дубликат не создан.
4. **Зоны — создание.** Создать ≥2 зон с номерами 1 и 2 на контроллере, включить, задать сезон. → список показывает зоны со статусом.
5. **Зоны — дубль номера.** Создать зону с занятым номером на том же контроллере. → ошибка «номер занят».
6. **Зоны — отключение ≠ удаление.** Отключить зону №1. → зона исчезает из активных; создать зону №1 заново — → ошибка (номер не переиспользуется).
7. **Программа — дни недели.** Создать программу: тип «дни недели», Пн–Пт, время 06:00, сезон 01.04–31.10. → маска хранится корректно, на странице отображается «Пн–Пт».
8. **Программа — интервал.** Создать программу типа «интервал», каждые 3 дня. → сохранено; взаимоисключение типов подтверждено.
9. **Программа без зон.** Создать программу и не добавлять зоны. → сохраняется без ошибок (по ТЗ допустимо).
10. **Состав программы.** В детальной странице программы добавить зоны разных контроллеров, изменить порядок. → порядок сохраняется; повторное добавление той же зоны → отклоняется.
11. **Программа — невалидные данные.** Время `25:70`, сезон `31.02`. → 422/ошибка формы, ничего не испорчено.
12. **Пользователи — создание.** Создать оператора без пароля. → показан сгенерированный пароль один раз.
13. **Защита админа.** Попытка удалить/понизить единственного админа. → отказ с понятным сообщением.
14. **Роли.** Войти под оператором: CRUD доступен; войти под viewer: кнопки редактирования скрыты, POST-запросы → 403.
15. **Сброс пароля.** Админ сбрасывает пароль оператора. → старая сессия оператора разлогинена, новый пароль работает.
16. **Настройки.** Изменить коэффициенты корректировок, сохранить. → значения сохранились после перезапуска сервера.
17. **Журнал.** Открыть дашборд/журнал. → все действия из пп. 2–15 присутствуют с автором и временем.
18. **Перезапуск.** Ctrl+C, повторный запуск. → данные целы, миграции не применяются повторно, логин работает.

## 4. Критерии приёмки Этапа 2 (DoD)

- [ ] `pytest server\tests -v` — все тесты проходят (регресс Этапа 1 включён);
- [ ] контроллеры/зоны создаются, редактируются, отключаются; физическое удаление зон отсутствует;
- [ ] правила номеров зон (уникальность в контроллере, запрет переиспользования) работают;
- [ ] программы обоих типов расписания, сезонность, состав зон с порядком;
- [ ] пользователи: CRUD, роли admin/operator/viewer, защита последнего админа;
- [ ] настройки сохраняются в БД и переживают перезапуск;
- [ ] каждое изменение попадает в журнал действий;
- [ ] ручная проверка по чек-листу §3 выполнена без замечаний.

## 5. Известные ограничения

- Файлы `data\poliv.db`, `logs\*`, `config\config.local.toml` не коммитятся (.gitignore) — при переносе на другую машину база начинается с нуля (админ генерируется автоматически).
- zone_locks — пока только таблица; логика блокировок активируется на Этапе 4–5.
